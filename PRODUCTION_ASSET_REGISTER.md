## C. Import procedure and safeguards

1. Ask founder which assets may be retained for ongoing production; obtain original full-resolution exports when possible rather than screenshots or compressed social previews.
2. Store on approved local/cloud storage with a stable folder, for example `production/<asset-type>/<date>-<slug>/`. **Example only; not a claim that folder exists.**
3. For each asset record the durable path/link, rights/licence, source type (generated / user-owned / licensed / social-download), date, tool/model/mode, prompt, input references, SHA-256, output dimensions, and whether it's founder-approved for actual publication.
4. Keep the working **blonde production persona** assets logically separate from the previous **brown-haired research reference set**, without altering or deleting old files.
5. Do **not** commit copied third-party Instagram performance videos or unlicensed source photographs to GitHub. Do not commit credentials or spend receipts containing personal/payment data.
6. If a previously listed file is missing in subsequent sessions, mark unavailable and request original export; never invent a new storage location or assert that an attachment is already backed up.
